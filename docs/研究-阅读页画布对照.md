## 0. 结论先行

| 项 | 结论 |
|---|---|
| **bug 总根因** | MReader 四类缺陷（累积漂移 / 开书闪动 / 停手跳动 / 占位换血）全部源于同一类问题：**成对映射与就绪门闸没有共用同一几何/同一真值**。legado-E 与 foliate-js 各自用「同源互逆」和「一次性落位」把这类 bug 消灭在结构上 |
| **三方各一条结构纪律** | legado-E：**进度真值=章内字符偏移，页码是二分查出的派生量**（`TextChapter.kt:226`）；foliate-js：**可见范围↔落位都从同一 DOM 几何推导**（`bisectNode` + `scrollToAnchor`），且**整节排完才上屏**；anx-reader：**进度=EPUB CFI（语义路径），像素坐标只活在当帧** |
| **MReader 现状定位** | 语义坐标 `(chapterHref, chapterPos)` 真值方向与 legado-E 一致；采样↔落位不动点（§2.84）已补上 foliate 式的「同源互逆」；**尚未补的是 legado 式的「排到目标才上屏、一次性落位」**——这正是任务 B 闪动的修法方向 |
| **路线建议** | **路线 A：坚持自研连续排版，移植三条结构纪律**（推荐，§5.1）；路线 B（页链式改造）成本高且推翻 §2.71 已定红线；路线 C（WebView+foliate-js）维持《选型》§1.2 的排除结论不变 |

## 1. legado-E（Kotlin/Android）：逐字列自绘 + 字符偏移真值

### 1.1 分层

`ChapterProvider`（object 单例，全局排版参数 / 视口几何 / paint 缓存，尺寸变更防抖 300ms）→ `TextChapterLayout`（1333 行，协程异步排版，`Channel<TextPage>` 逐页产出）→ 实体 `TextChapter / TextPage / TextLine / TextPos` + `column/`（`TextColumn / ImageColumn` 逐字列）→ `ContentTextView`（自绘 `onDraw`）+ `ReadView / PageView` + `delegate/`（7 种翻页动画）。

### 1.2 布局算法（`TextChapterLayout.kt`）

- `setTypeText`（:900-1027）逐段落用 `StaticLayout / ZhLayout` 断行 → 逐行 `prepareNextPageIfNeed(durY + textHeight)` 判页满（:1269，`requestHeight > visibleHeight` 封页，双页先填左列）→ 逐字 `addCharToLine` 产出 `TextColumn(start, end)` 精确 x 区间。
- 三种行排列：`addCharsToLineFirst`（缩进+两端对齐）、`addCharsToLineMiddle`（两端对齐，`wordSpacing` 或 `extraLetterSpacing` 均摊 `residualWidth`）、`addCharsToLineNatural`（自然排）；`exceed`（:1242）超宽压缩回拉。
- `measureTextSplit` 做字素簇合并；`calcTextLinePosition`（:1029）逐行累加 `charSize + isParagraphEnd` 得行首章内字符偏移。

### 1.3 坐标与进度（这是它最值得抄的部分）

- 几何：`TextLine.lineTop / lineBase / lineBottom`（像素，`upTopBottom` :103 由 `durY + fontMetrics` 推）；语义：`chapterPosition`（行首字符偏移）+ `pagePosition`；`TextPos = (relativePagePos, lineIndex, columnIndex)` 三维（选词/书签用）。
- **进度真值 = `ReadBook.durChapterPos`（字符偏移）**，页码是派生量：
  - 字符→页：`getPageIndexByCharIndex` **二分**（`TextChapter.kt:226` `fastBinarySearchBy`）；
  - 页→字符：`getReadLength(pageIndex) = pages[i].chapterPosition`；
  - `setPageIndex / skipToPage` 一律 `durChapterPos = getReadLength(index)`（`ReadBook.kt:421-432`）；`saveRead` 落 `book.durChapterPos`（:908-917）；开书恢复 `durPageIndex = getPageIndexByCharIndex(durChapterPos)`（:503-505）。
  - **两个方向都从同一 `pages[].chapterPosition` 表推导 ⇒ 天然互逆**，不存在 MReader §2.84 那类「采样一套口径、落位另一套」的复利漂移。
- **上屏门闸**：排版到目标页（`containPos(durChapterPos)`）才上屏，此前显示**整页占位页**；点击/跳转是**一次性落位**（无「估算→精确」两段，`ReadBook.kt:452-468, 728-746`）。

### 1.4 滚动模式（`ScrollPageDelegate` + `ContentTextView`）

**页链式滚动**（非连续排版）：`pageOffset`（0 ~ −textPage.height）累积，越界即 `pageFactory.moveToNext/Prev` 换页并回补高度（`ContentTextView.kt:145-177`）；绘制=当前页+下页+下下页堆叠（`relativeOffset` :720-726）；停手 `fling` + `calcNextPageOffset`（`ScrollPageDelegate.kt:155-169`，**保留一行**：`lastLineTop − paddingTop`）；触点映射 `touch()`（:391-428）逐 `relativePos`→行 `isTouch(y)`→列 `isTouch(x)` 得 `TextPos`。

### 1.5 渲染优化

`CanvasRecorder` 页级/行级录制缓存；`checkFastDraw` 整行 `drawText` 快路径 vs 逐列绘制；`preRenderPage` 渲染线程预渲染 prev/cur/next/nextPlus 四页；翻页动画期只回放整页截图。

## 2. legado_flutter-2026：移植不完整的反面教材

- **UI 在用路径 = `PageView.builder` + `Text` widget 拼装（非 Canvas 自绘）**；`ChapterLayoutProvider` 贪心逐行分页（`TextPainter.computeLineMetrics`）。
- **测量/渲染不同源**：分页含 letterSpacing/fontWeight、渲染丢——同一类「两套口径」病，比 MReader §2.84 更重。
- **进度只存页码且不恢复**：`durChapterPos` 被当页码写、进书恒第一页——字符偏移真值在移植中丢失。
- `lib/services/reader/` 有一套按文档写好的 Canvas+语义坐标完整方案（`ReaderView / ReaderPainter / Paginator / ReadingPositionManager / PaginationCache`）但**全部未接 UI**（死代码）；仿真翻页/渐进渲染亦为死代码。
- **教训**：双轨并存（活的拼装版 + 死的 Canvas 版）等于两套模型都不能信。MReader 引以为戒：任何「另起一套更好的」必须当日接线或当日删除。

## 3. anx-reader（Flutter + WebView 内嵌 foliate-js）：把排版外包给浏览器

### 3.1 架构

- 正文渲染**完全不在 Flutter 侧**：foliate-js（GNOME Foliate 的 JS 排版引擎，`assets/foliate-js/src/`）跑在 `flutter_inappwebview` 里；`book_player_server.dart` 起 **shelf 本地 HTTP**（127.0.0.1）向 WebView 喂 EPUB / 字体 / 背景图 / foliate-js 资源。`lib/` 内 CustomPaint/TextPainter 仅分享卡片用。
- **分页 = 浏览器 CSS 多栏**：`columnize()`（`paginator.js:283-318`）设 `column-width/column-gap/column-fill:auto` + 固定高度，断页由浏览器排版引擎完成；`expand()`（:345-394）量 `contentRange.getBoundingClientRect()` 得 `pageCount = ceil(contentSize / size)`，页=栏=平移一屏。**自己不写断行/断页算法**。
- 滚动/翻页全在 JS 侧：`scrollBy`/`#scrollToPage` 平移栏位，`snap()`（:781-844）按速度阈值 0.3 吸附到整页边界（限单页位移）；scrolled 模式 `#afterScroll` **relocate debounce 200ms**（:1147-1155，滚动中不跑 `getVisibleRange`）。

### 3.2 进度语义 = EPUB CFI（语义路径）

- 每次停稳 `#doRelocate`（:1160-1177）：`getVisibleRange`（TreeWalker 找可见节点 + `bisectNode` 二分找字符级边界，:38-112）→ `view.js:400-403` `getCFI = baseCFI + CFI.fromRange(range)` → `onRelocated` 事件上抛 `{cfi, percentage, chapterCurrentPage, chapterTotalPages, bookmark, writingMode}`。
- 全书百分比 `SectionProgress`（`progress.js:58-113`）：按节大小加权 fraction，`getProgress`/`getSection` **互逆**（fraction→节内比例→fraction 的往返恒等，与 MReader §2.84 同一思想，独立实现了一遍）。
- 进度保存极薄：`saveReadingProgress()`（`epub_player.dart:984-993`）`book.lastReadPosition = cfi` + `bookDao.updateBook`；恢复=开书把 cfi 交给 JS `resolveCFI` → `scrollToAnchor`。
- **像素坐标不落盘、不跨帧**：`onSelectionEnd` 的 pos 矩形只用于当帧弹菜单；一切持久坐标都是 CFI。注解/书签/搜索命中也全存 CFI。

### 3.3 Dart↔JS 桥（`epub_player.dart:647-902`）

17 个 `addJavaScriptHandler`：`onRelocated`（进度）/ `onClick`（热区，`coordinates_to_part.dart` 九宫格 0.33/0.66 三分——与 MReader §2.83 同构）/ `onSetToc` / `onSelectionEnd`/`onSelectionCleared` / `onAnnotationClick` / `onSearch` / `handleBookmark` / `translateText` / `onImageClick` / `onPushState` 等；Flutter→JS 则 `evaluateJavascript` 调 `nextPage()/goToPercent()/changeStyle()`。TXT 经 `convert_to_epub/` 转 EPUB 后同管道。

### 3.4 代价（《选型》§1.2 排除理由，本研究复核仍成立）

WebView 重量级（内存/启动/冷渲染）、玻璃态与原生手势整合受限、TXT 强制转 EPUB、平台 WebView 差异（尤其 Windows/Linux）、排版能力上限=浏览器 CSS。**路线 C 维持排除**。

## 4. MReader 四类缺陷 × 模型差异根因

| # | 缺陷 | 现状 | 根因（对照三方） | 三方怎么结构性消灭它 |
|---|---|---|---|---|
| 1 | 重复开关书累积漂移 | **已修**（§2.84，`b924fcd`） | `sampleNow` 均匀折算与 `offsetFor` 行表落位不同源，闭环复利 | legado-E：字符↔页双向共用 `pages[].chapterPosition`；foliate：`getProgress/getSection` 互逆、可见范围与落位共用 DOM 几何。**成对映射必须同几何**是共同不变量 |
| 2 | 开书闪动 | 已诊断未修（任务 B） | ①转场放行太早（估算落位+`_pendingLand` 二次精确 ⇒ 视口大跳）②占位带满屏换血（`_repairReachable` 扩窗补 96dp 带，邻章 pop-in）③冷缓存 | legado-E：**排到目标页才上屏 + 一次性落位**，占位是整页原子单位；foliate：整节 `expand()` 排完才显示、页数一次算准。**「两段式落位」是 MReader 独有的病灶** |
| 3 | 慢滚停稳偶发大跳 75~149px | 未根治（§2.75 §7） | 停手重锚与增量补页竞争（根因待日志） | legado：页链滚动 `calcNextPageOffset` 保留一行、无连续排版重锚；foliate：scrolled relocate debounce 200ms、滚动中不算可见范围。**停手瞬间的语义采样要让位于稳定几何** |
| 4 | 占位带换血 | 与 #2 同链 | 96dp 占位块是「伪行」，补齐时在可见区内整段替换 | legado：占位=整页，换血只发生在翻页原子动作里；foliate：无占位概念（排完才上）。**占位要么原子（整页/整章）、要么不可见** |

**一句话**：MReader 的语义坐标方向（`(chapterHref, chapterPos)`）与 legado-E 一致，§2.84 已把「互逆」补上；剩下三个 bug 全部卡在**「就绪与落位的时序」**——legado-E 用「排到目标才上屏、一次性落位」、foliate 用「整节排完才上屏」，都是**宁可晚显示，不显示半成品**。

## 5. 架构级改进建议（供拍板）

### 5.1 路线 A（推荐）：坚持自研连续排版，移植三条结构纪律

不换模型（§2.71 连续排版红线不动），把三方的结构纪律变成 MReader 的硬约束：

1. **成对映射同几何**（已落地 §2.84）——固化为规范：凡新增「像素↔字符」映射，必须同表推导 + 往返恒等用例 + 变异判红。
2. **一次性落位 / 排到目标才上屏**（任务 B 修法方向）——开书转场放行门闸从「首帧上屏」升级为「**精确落位完成 + 视口真身**」；占位带补齐只允许发生在**视口外**，视口内不换血；`_repairReachable` 扩窗与上屏解耦（红线不变：窗口不加上界）。
3. **停手采样让位稳定几何**（#3）——停手瞬间不做语义重锚采样或采样延迟到几何稳定（参考 foliate relocate debounce 200ms 的思想），并配合真机 `paged.move`/`paged.stop` 留痕定位 75~149px 大跳的触发链。

代价：要继续自研还债（选词、双页、竖排等都得自己做）；收益：可控、性能上限最高、玻璃态与既有 460 条 reader 测试资产全保留。

### 5.2 路线 B：改造为 legado 页链式模型（不推荐）

进度真值与翻页原子性最好，但推翻 §2.71「滚动模式=连续排版、禁页边界吸附」的既定拍板，等于重做 M-PAGE 分页引擎与滚动链路，冲击面覆盖 §2.76/§2.79/§2.80/§2.84 已验收的全部滚动语义。仅当负责人愿意推翻滚动模式拍板时才考虑。

### 5.3 路线 C：WebView + foliate-js（维持排除）

见 §3.4 与《选型-阅读呈现引擎.md》§1.2。anx-reader 的**进度语义（CFI 思想）值得抄**，载体不值得抄。

## 7. 对任务 B（开书闪动）修法的直接输入

诊断结论（2026-10-10 已存档 `.workbuddy/memory/2026-10-10.md`）三条机制链，对照研究后修法收敛为：

1. **转场放行门闸升级**（对齐 legado「排到目标页才上屏」）：`_signalOpenReady` 放行条件从「首帧上屏」改为「目标语义坐标精确落位完成且视口已稳定」；估算落位仅作过渡帧、不作为放行条件；`_pendingLand` 二次精确落位完成前不放行转场。
2. **占位换血出视口**（对齐 legado 整页占位 / foliate 整节才显）：`_repairReachable` 扩窗补齐允许在视口外补 96dp 占位带，但**视口内已上屏内容不被占位块替换**；邻章换血时机推迟到目标章真身落位之后（红线不变：窗口不加上界，防 `_jumpPaged` 静默 return）。
3. **冷缓存收口**：`PaginationScheduler` 生命周期脱离 `State` 新建（开书重入不丢缓存）。

修法实施顺序建议：先 1（收益最大、风险最小），再 2，最后 3；每步各自红灯测试 + 变异判红 + 两段提交。
