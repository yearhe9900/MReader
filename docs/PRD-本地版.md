### 范围声明

本期**只做本地阅读**。**明确排除书源（legado 书源解析、网络搜索、在线书城）及一切联网能力**。

### 一句话定位

**一个无广告、无账号、纯本地、中文排版优先的 EPUB 阅读器**——把本地书读好，别的一概不做。

### 本文档的事实基线

本文档的产品现状描述**以实际代码为准**（已通读 `README.md`、`lib/main.dart`、`lib/ui/reader_page.dart`、`lib/ui/reader_settings_bar.dart`、`lib/model/epub_book.dart`、`lib/epub/epub_parser.dart`、`lib/epub/section_extractor.dart`、`lib/epub/text_codec.dart`、`pubspec.yaml`、`git log`）。过程中发现上游任务描述有若干处与实际代码不符，已在下文 §2.3 逐条注明，**均以代码为准**。

## 2. 产品目标与定位

### 2.1 要解决的问题

| # | 问题 | 现状证据 |
|---|---|---|
| 1 | 手上有本地 EPUB（含大量中文老书、脏书），手机/桌面上没有一个「打开就能舒服读完」的工具 | 现有开源阅读器要么带书城/广告/账号，要么排版粗糙 |
| 2 | 中文老书编码混乱（GBK、声明撒谎、Big5），多数阅读器直接乱码 | 本项目解析层已能正确解码 GBK 与「声明 utf-8 实为 GBK」，这是已验证的差异化能力 |
| 3 | 现有 App 每次看书都要重新选文件，读完就走丢 | 当前代码无书架、无进度持久化 |
| 4 | 长篇小说需要目录跳转、需要记住读到哪、需要夜间可读 | 当前无 TOC / 无进度 / 无主题 |

### 2.2 不解决的问题（本期的非目标）

- 不做书源、不做在线书城、不做网络搜索、不做任何联网功能。
- 不做内容获取（下载、抓取、同步），只处理用户**已经存在本地**的文件。
- 不做社交（评论、划线分享、书单）、不做账号体系。
- 不做 AI 相关（摘要、翻译、问答）、不做 TTS 朗读。
- 不做商业变现（广告、会员、统计埋点）。
- 不做跨设备同步（云同步、WebDAV、坚果云）。

### 2.3 现状与上游描述的差异（以代码为准）

| # | 上游描述 | 代码实际 | 影响 |
|---|---|---|---|
| 1 | 书源解析在 `lib/source/` | `lib/source/`（10 个 Dart 文件）**另有** `lib/ui/source/`（`source_list_page.dart`、`source_detail_page.dart`）；测试侧有 `book_source_*.dart`、`capability_registry_test.dart`、`source_diagnostic_platform_test.dart`、`test/fixtures/shenshi.json`；`git log` 显示书源功能由 5 个 commit 实现 | 书源模块体量比描述大得多，是**已完成的功能**而非占位。「隐藏入口」不会让它消失，测试仍会跑 |
| 2 | `test/` 下只有 `widget_test.dart`、`epub_fixtures_test.dart` | 实际 **9 个**测试文件 | 回归面比描述大 |
| 3 | 首页是「选文件 → 解析 → 阅读页」 | 首页 AppBar 标题为 `阅读M · 可行性验证`，页面是两个入口并列的**验证台**，含书源入口 | 首页需要整体重做为「书架」 |
| 4 | 阅读页无调试信息 | `reader_page.dart` 的 AppBar 副标题含 `$total 章 · 首章 ${...} 字节` 诊断信息 | 产品化必须摘掉 |
| 5 | `<br>` 被当作段落分隔 → 诗歌多空行 | 准确。机制是：`_walk` 遇 `<br>`/`<hr>` 执行 `_flush`，`<br>` 把每一行切成**独立段落**，渲染时用 `'\n\n'` 连接 → 行内换行被放大成段间距 | 需修正为行内换行语义 |
| 6 | 表格排版丢弃 | 比「丢弃」更糟：`table/thead/tbody/tfoot/tr/td/th` 全在 `_blockTags` 里，每个单元格文字被 flush 成独立段落，二维结构彻底退化为竖直堆叠 | 表格类书籍阅读体验接近不可用 |
| 7 | 整本书解压后常驻内存，含大量图片的 EPUB 也占这份内存 | 需分两个口径：**峰值** ≈ 原始 zip 字节 + 解压后全部字节（图片包含在内，`parseEpub` 期间的 `files` map 持有全部条目）；**稳态** ≈ 仅各章 XHTML 之和（`EpubSection.rawBytes` 持有；图片字节随后可被 GC）。`_contentOf` 对 `Uint8List` 是引用、对 `List<int>` 才拷贝 | 结论方向不变（大书内存风险真实存在），但**峰值**才是 OOM 的主因；另 `file_picker` 的 `withData: true` 会让插件层再持有一份原始字节，需实测 |
| 8 | 改字号后滚动位置保持 | 「像素级 offset 保持」成立，但**内容高度会变** → 视觉上会漂移，漂移量正比于当前位置之前内容的累计高度变化；读长书时表现为「跳走好几百字」 | 需要升级为「锚定当前段落」而非「保持像素偏移」 |

## 3. 目标用户与核心使用场景

### 3.1 目标用户

| 维度 | 描述 |
|---|---|
| 主要用户 | 项目负责人本人（Android 开发者） |
| 主要设备 | 小米手机（HyperOS / Android 16）；次要：Windows 桌面 |
| 阅读偏好 | 中文排版质量优先、开源、无广告、无账号、无联网 |
| 书源构成 | 本地 EPUB 为主，预计含中文老书（GBK）、网络小说转制 EPUB、少量 TXT（待确认，见 §9 Q2） |
| 参照物 | 已实际使用过 **Anx Reader**（`com.anxcye.anx_reader`，开源 Flutter EPUB 阅读器）；功能取舍以其形态为下限参照，不追求超越 |

### 3.2 核心使用场景（3-5 个具体场景）

| # | 场景 | 触发 | 期望行为 | 现状 |
|---|---|---|---|---|
| S1 | **通勤续读**：地铁上掏出手机接着昨晚的进度读 | 打开 App | 直接落在「正在读的第 3 本书」，恢复到第 12 章第 3 段附近，不用重新找文件 | ❌ 需重新选文件、进度全丢 |
| S2 | **睡前夜读**：关灯后读半小时，不要太刺眼 | 打开阅读页 | 切到夜间主题，背景深色、文字不刺眼；调完亮度/字号不丢失阅读位置 | ❌ 无主题；改字号会视觉漂移 |
| S3 | **长篇跳章**：读一本 300 章的合集，想直接跳到「第 87 章」 | 点目录 | 目录按层级列出章节，点一下立刻定位到该章开头 | ❌ 无 TOC |
| S4 | **脏书打开**：从各种来源收集的 EPUB，编码/结构不规范，且可能很大（50MB+） | 导入 | 能正确解码中文、能打开；即便很脏也给出可读提示，不白屏不崩溃 | 🟡 解析层已能容错；但大书有卡顿/OOM 风险 |
| S5 | **管理书库**：手机上攒了 20 本，想删掉读完的、按最近阅读排序 | 进书架 | 书架显示封面+书名+作者+阅读进度；可排序、可删除 | ❌ 无书架、无多书管理 |

## 4. 用户故事

格式：**作为**〔角色〕，**我希望**〔能力〕，**以便**〔收益〕。按需求域分组。

### 4.1 书库管理（Library）

- US-01：作为读者，我希望打开 App 就能看到我导入过的所有书，以便不用每次重新去文件管理器里翻找。
- US-02：作为读者，我希望导入一本 EPUB 后它就被留在 App 里，以便下次直接从书架点开。
- US-03：作为读者，我希望在书架上看到每本书的封面、书名、作者和「已读百分比」，以便快速挑出想继续读的那本。
- US-04：作为读者，我希望按「最近阅读」排序书架，以便最近在读的书排在前面。
- US-05：作为读者，我希望长按删除一本书（含其阅读进度），以便清理读完的书。
- US-06：作为读者，我希望导入重复的书时被告知而不是默默多出一本，以便书架不会变乱。

### 4.2 阅读体验（Reading）

- US-07：作为读者，我希望重新打开一本书时回到上次读到的位置，以便不用凭记忆找。
- US-08：作为读者，我希望阅读页有关闭全部调试信息、只剩正文，以便沉浸阅读。
- US-09：作为读者，我希望阅读时点击屏幕中部能呼出/收起控制条，以便既不遮挡正文又能随时调设置。
- US-10：作为读者，我希望阅读页随时能看到「全书进度百分比」，以便判断还要读多久。

### 4.3 导航与定位（Navigation）

- US-11：作为读者，我希望打开书内目录并按层级浏览章节，以便跳到任意一章。
- US-12：作为读者，我希望目录打开时自动高亮我当前所在章节，以便知道自己在哪。
- US-13：作为读者，我希望在阅读页直接显示当前章节名，以便随时确认读到哪一章。

### 4.4 排版与外观（Typography）

- US-14：作为读者，我希望调整字号并立即看到效果，以便不同场景下都能看清。
- US-15：作为读者，我希望调整行距和页边距，以便控制每屏信息量和眼睛舒适度。
- US-16：作为读者，我希望在日间/夜间/跟随系统之间切换，以便白天和关灯后都舒服。
- US-17：作为中文读者，我希望段落有首行缩进、标题居中、加粗生效，以便读起来像正规出版物。
- US-18：作为读者，我希望诗歌、地址块这类用 `<br>` 换行的内容**只在行内换行**，以便不被撑成一行一段的大空隙。
- US-19：作为读者，我希望调整字号/主题后**不丢失当前阅读位置**，以便改完设置不用重新找。

### 4.5 内容完整性与兼容性（Content）

- US-20：作为读者，我希望**书里的图片能显示出来**，以便插图、地图、谱例不丢。
- US-21：作为读者，我希望点书里的脚注/内部链接能跳转，以便看到注释原文。
- US-22：作为读者，我希望被标成 `linear="no"` 的附录/注释也能读到，以便内容完整。
- US-23：作为读者，我希望打开一本漫画型（固定版式）EPUB 时被明确告知「暂不支持」，以便不误以为是软件坏了。
- US-24：作为读者，我希望支持本地 TXT 文件，以便读手头的网络小说。
- US-25：作为读者，我希望在书内搜索关键词并跳转到命中位置，以便找回某段内容。

### 4.6 性能与稳定性（Performance）

- US-26：作为读者，我希望打开 50MB 级大书时不闪退、不长时间无响应，以便正常读大合集。
- US-27：作为读者，我希望超过 10 万字的超大单章也能正常滚动，以便不被排版卡死。
- US-28：作为读者，我希望滚动时全程流畅，不要滚一下就卡一下。
- US-29：作为读者，我希望遇到损坏文件时看到中文错误提示，以便知道出了什么问题。

### 4.7 数据安全（Data Safety）

- US-30：作为读者，我希望阅读进度、书签、设置在任何异常退出后都不丢，以便不用反复重建。

## 5. 需求池（核心章节）

**优先级定义**：P0 = 必须（缺了就不成产品）；P1 = 应该有（决定是否「用得舒服」）；P2 = 可以有（打磨项）。

**本期 P0 的最小完整闭环**定义为：**导入并留存书籍 → 书架可见 → 打开 → 有目录可跳 → 记住进度 → 设置可调且可持久化 → 重新打开能续读 → 大书不崩**。以下 P0 全部服务于这条闭环。

### 5.1 P0 — 必须（共 12 条）

| 编号 | 需求名 | 描述 | 验收要点（可验证） |
|---|---|---|---|
| **P0-01** | 书架首页 | 用「书架」替换现有的可行性验证台首页。展示已导入书籍列表（封面缩略图 + 书名 + 作者 + 已读百分比 + 最近阅读时间），顶部提供「导入书籍」入口。空书架显示空态引导（一句说明 + 导入按钮）。移除首页的「书源解析」入口。 | ① 全新安装后进入 App 落在书架页，不再出现「阅读M · 可行性验证」字样；② 空态文案可见且含导入按钮；③ 导入 3 本书后列表显示 3 项，每项含封面位、书名、作者、百分比；④ 首页无书源入口 |
| **P0-02** | 书籍本地留存 | 导入时把选中的 EPUB **复制进 App 私有数据目录**并登记到书库索引；重启 App 后无需重新选择文件即可打开。重复导入同一本书（按内容摘要判重）应提示「已存在」而非新增一条。 | ① 导入后杀掉进程重启，书架仍能列出该书并成功打开；② 把原文件从下载目录删除后，App 内仍能打开该书；③ 同一文件导入两次，书架仍只有 1 条且出现「已存在」提示 |
| **P0-03** | 书库索引持久化 | 书库清单（含每本书的文件路径、元数据、导入时间、最后阅读时间）持久化到本地。索引文件损坏或指向的文件缺失时，逐条降级（标记「文件已丢失」）而不是整库崩溃。 | ① 手工把索引某条指向的文件删掉，重启后书架仍能列出其余书，缺失项显示「文件已丢失」且可删除；② 手工把索引文件写成非法内容，App 仍能启动并给出可读提示，不崩溃 |
| **P0-04** | 阅读页产品化 | 阅读页移除全部诊断信息（当前 `AppBar` 副标题里的「N 章 · 首章 N 字节」）。产品态下 `AppBar` 只显示书名；显示当前章节名与全书进度百分比。release 构建下不得出现任何调试文案。 | ① release 构建中阅读页找不到「章 ·」「字节」等诊断字样；② 阅读页可见当前章节名与进度百分比；③ debug 构建允许保留诊断信息但需与产品文案样式区分 |
| **P0-05** | 沉浸式控制条 | 控制条默认**隐藏**。点击屏幕中部区域呼出（底部弹出，含字号/行距/页边距/主题/目录入口），点击正文区域或再次点击中部收起。控制条收起时正文区域最大化。 | ① 进入阅读页时控制条不可见；② 点击中部后控制条出现；③ 点击正文后控制条消失；④ 控制条隐藏状态下正文可用高度大于显示状态 |
| **P0-06** | 目录（TOC）解析与跳转 | 解析 EPUB 的 `nav.xhtml`（EPUB3）或 `toc.ncx`（EPUB2）构造章节树（保留层级与标题）；阅读页提供目录入口，点击某项跳转到对应章节。TOC 缺失时降级为「按 spine 顺序生成的平坦章节目录」。二者皆不可用时不得报错。 | ① 打开一本含 nav.xhtml 的 EPUB，目录层级与书内一致；② 打开一本含 toc.ncx 的 EPUB（fixture `fx06` 类）目录可用；③ 打开一本无 TOC 的书，目录仍能列出全部 spine 章节；④ 点击目录项后阅读页定位到该章且目录项高亮 |
| **P0-07** | 目录当前章高亮 | 目录打开时自动滚动并高亮当前所在章节，跳转后高亮同步更新。 | ① 滚到第 5 章后打开目录，第 5 章项处于高亮态且已滚入可见区域；② 从目录跳到第 20 章后再次打开目录，高亮在第 20 章 |
| **P0-08** | 阅读进度持久化与续读 | 退出阅读页（返回/切后台/杀进程）时保存进度，粒度 = **章节索引 + 章内相对位置（0.0~1.0）**，并记录保存时间。重新打开该书时恢复到保存位置，并弹出一次可关闭的轻提示（如「已恢复上次阅读位置」）。到达全书末尾时进度记为该书 100%。 | ① 读到第 12 章中部，返回书架再打开，落点与离开时视觉位置误差在 ±1 屏内；② 杀进程后重开，同上；③ 读完全书后书架进度显示 100%；④ 从书架「开始阅读」一本从未读过的书，从第 1 章开头开始 |
| **P0-09** | 阅读设置面板与持久化 | 提供字号（`12~36`，步进 1）、行距（`1.0~2.6`）、页边距（三档或滑块）设置项；设置改动立即生效，并作为**全局默认值**持久化，下次打开任何书沿用。阅读页内提供「恢复默认」。 | ① 调大字号后立即生效；② 退出 App 重进并打开另一本书，字号/行距/页边距与上次一致；③ 点「恢复默认」后回到默认值（字号 18 / 行距 1.6 / 页边距 16）且该默认值被持久化 |
| **P0-10** | 设置变更后锚定当前段落 | 改变字号/行距/页边距/主题导致内容高度变化时，阅读位置必须**锚定到当前正在阅读的段落**，不得出现「跳走一段/几百字」的现象。 | ① 在第 12 章第 3 段处把字号从 18 连续调到 30，调整后该段仍停留在屏幕可视区域内（允许偏移 ±1 段）；② 同理调行距、切主题；③ 在第 1 章与最后一章各测一次，均成立 |

### 6.3 关键交互流程

**流程 A — 首次使用（空书架 → 开始阅读）**

```
启动 App
  → PG-01 书架（空态）
  → 点「导入本地书籍」/ FAB
  → 系统文件选择器（仅 .epub；P1 后含 .txt）
  → 用户取消 → 回到书架（无副作用）
  → 选中文件
      → 复制进私有目录 + 登记索引
      → 解析元数据/封面/TOC
          ├─ 成功 → SnackBar「已加入书架」→ 书架出现新书
          └─ 失败 → 对话框显示可读原因 → 不加入书架、不留垃圾文件
  → 点书卡 → PG-02 阅读页（从第 1 章开头）
```

**流程 B — 续读（核心闭环）**

```
启动 App → 书架（按最近阅读排序）
  → 点「正在读」的书
  → 读取该书进度记录（章节索引 + 章内比例）
      ├─ 有记录 → 定位到该处 → SnackBar「已恢复到上次阅读位置」
      └─ 无记录 → 第 1 章开头
  → 阅读（滚动）
  → 返回 / 切后台 / 杀进程
      → 写入进度（章节索引 + 章内比例 + 时间戳）
  → 书架该书的百分比同步更新
```

**流程 C — 调设置不丢位置**

```
阅读中 → 点屏幕中部 → 控制条呼出
  → 调字号 A+ / 拖行距 / 换主题
      → 立即重排
      → 【关键】以「当前正在阅读的段落」为锚点重算滚动位置
      → 锚点段落仍在视口内（±1 段）
  → 点正文 → 控制条收起
```

**流程 D — 目录跳转**

```
阅读中 → 控制条「目录」→ PG-03
  → 面板打开并自动定位/高亮当前章
  → 点第 87 章
      → 关闭面板，正文跳到第 87 章开头
      → 进度指示与目录高亮同步更新
      → 若该章尚未解析 → 显示章内加载占位（不白屏）
```

**流程 E — 打开大书 / 脏书**

```
选中 50MB EPUB
  → 显示可取消的 loading（进度提示）
  → 后台 isolate 解压 + 解析结构（UI 保持响应）
      ├─ 成功 → 进入阅读页（正文按需解析）
      ├─ 失败（非 zip/缺 container/OPF 坏/spine 空）→ 对话框可读中文原因
      └─ 固定版式 → 「暂不支持」对话框
  → 阅读中滚动到新章节 → 后台解析该章 → 短暂占位 → 内容出现并缓存
```

## 7. 非功能需求

### 7.1 性能

| 编号 | 指标 | 目标（本机小米 Android 16 / Windows 桌面各测一次） |
|---|---|---|
| NF-P1 | 冷启动到书架可交互 | ≤ 2 秒；已导入 ≥ 30 本书时 ≤ 3 秒 |
| NF-P2 | 打开书耗时 | 10MB 书 ≤ 2 秒；50MB 书 ≤ 10 秒，且全程有可见进度反馈、UI 不冻结 |
| NF-P3 | 章节首次解析 | 单章 ≤ 200ms；解析在后台 isolate 进行，主 isolate 不阻塞 |
| NF-P4 | 滚动流畅度 | 连续滚动 30 秒无可见掉帧、无冻结；滚动中不触发重解析 |
| NF-P5 | 超大单章 | 单章 > 10 万字符时首帧 ≤ 1 秒，滚动仍可响应（按段渲染，不整体布局） |
| NF-P6 | 书内搜索（P1） | 100 章规模 ≤ 3 秒返回结果，可取消 |

### 7.2 内存

| 编号 | 指标 | 目标 |
|---|---|---|
| NF-M1 | 稳态内存 | 打开书后应显著低于「全书解压后大小」——非章节资源（图片/字体/CSS）必须可被释放 |
| NF-M2 | 峰值内存 | 50MB 级 EPUB 打开过程不 OOM（以「不闪退 + 无 OutOfMemory 日志」判定） |
| NF-M3 | 图片缓存（P1） | 图片解码缓存设上限，连续滚动大图量书籍时内存不单调增长 |
| NF-M4 | 章节正文缓存 | 已解析章节的缓存应有上限策略（如 LRU），避免读完整本书后缓存等于全书正文 |

### 7.3 兼容性

| 编号 | 约束 |
|---|---|
| NF-C1 | 渲染路线固定：**纯 Dart 解析 + 纯 Flutter 自绘 Widget，不引入 WebView / foliate-js** |
| NF-C2 | 平台一致性：维持「同一份 `lib/` 源码跑六个平台（Android / iOS / Windows / macOS / Linux / Web）」；**若为满足某平台引入平台特定 API，须显式隔离并记录（见 §9 Q1）** |
| NF-C3 | 状态管理只用 `StatefulWidget` + `setState`；**禁止** Riverpod / Provider / Freezed / 代码生成 |
| NF-C4 | 不向工程内塞字体文件；中文靠系统字体 |
| NF-C5 | `archive` 锁 `^3.6.1`（4.x 改变 `ArchiveFile` API） |
| NF-C6 | Flutter 3.44.9-stable（Dart 3.12.2），SDK 约束 `^3.12.2` |
| NF-C7 | 文件格式支持范围：本期 P0 仅 `.epub`（含 EPUB2 / EPUB3 流式）；`.txt` 见 P1-07 |
| NF-C8 | 已建立的 14 本现实脏书回归契约（`test/fixtures/` + `baseline.json`）必须保持通过，不得因产品化改动而回归 |
| NF-C9 | 最低适配：手机竖屏为主要形态，同时保证桌面窗口可自由缩放不破版 |

### 7.4 数据安全（本地数据不丢）

| 编号 | 要求 |
|---|---|
| NF-D1 | 进度、设置、书签、索引在**任意时刻被强杀**后不得丢失已提交的写入（采用「写临时文件 → 原子替换」策略，避免半截文件） |
| NF-D2 | 索引或数据文件损坏时**逐条降级**：能列出多少列多少，坏条目标记并可清理，绝不整库不可用 |
| NF-D3 | 导入过程失败不得留下孤儿文件（先落临时名，索引登记成功后再改正式名） |
| NF-D4 | 删除书籍时同时清理正文文件、封面缓存与阅读数据，不留残留 |
| NF-D5 | **零网络**：本期不申请任何网络权限、不发起任何网络请求、不接入任何统计 SDK |

### 8.1 本期做（P0 闭环）

1. 书架：列表、导入、打开、删除、最近阅读排序、进度展示。

| **Q1** ⚠️ | **是否接受为「书架持久化 / 进度持久化 / 设置持久化」引入首个平台相关依赖？**<br>现有约束是「零平台特定 API，六平台共用同一份 `lib/` 源码，`lib/` 内无 `dart:io`」。但书架要长期保存文件、进度要落盘，纯 Dart 无法做到（Web 的 `dart:io` 不存在）。 | **接受，但严格收敛**：① 只引入最小必要依赖（应用私有目录定位 + 键值/文件读写）；② 在 `lib/` 内定义**抽象接口**（如 `StoragePort`），各平台提供实现，UI 层只依赖接口；③ Web 端实现为内存态并在 UI 上坦诚降级；④ 抽象接口的纯 Dart 部分保持可单测。 | 这是**本期最大的技术风险，也是最大的设计决策**。不引入 → 书架和进度只能「会话内有效」，本期的 P0 闭环（续读）直接不成立，产品价值为零。引入 → 「六平台零平台 API」这条长期约束首次破例，跨平台一致性成本从「零」变为「需要维护 6 份实现（其中 4 个桌面/移动平台通常共享同一实现）」。**建议接受，但用接口隔离把影响面锁死在一个文件里。** | 🔴 高 |

## 10. 里程碑建议

> 按 P0 → P1 → P2 分批，**不写具体工期天数**。每批结束时应有一个可独立交付、可被验收的版本。

### M1 — 本地阅读闭环（P0，12 条）

**范围**：P0-01 ~ P0-12（书架、留存、索引、阅读页产品化、控制条、目录、当前章高亮、进度续读、设置面板、位置锚定、主题、大书性能）。

**交付判定（全部满足才算 M1 完成）**：

1. 全新安装 → 导入 3 本 EPUB → 书架显示 3 项 → 杀进程重启 → 仍能打开且续读。
2. 一本 300 章的书：目录可跳章、当前章高亮、进度百分比正确。
3. 调字号/行距/主题后阅读位置不跳走（±1 段内）。
4. 50MB 级书能打开不闪退，滚动不冻结。
5. 现有 14 本脏书回归测试全部通过（NF-C8）。
6. release 构建中不存在任何调试文案。

**前置依赖**：Q1 必须先拍板（它决定 M1 能否成立）。

### M2 — 阅读体验增强（P1，14 条）

**范围**：P1-01 ~ P1-14。建议内部再分两小批：

- **M2a 排版与内容**（优先，直接决定「读起来像不像正规书」）：P1-02（CSS 语义）、P1-03（`<br>` 修正）、P1-04（表格）、P1-01（图片）、P1-05（脚注跳转）、P1-06（`linear="no"`）。
- **M2b 功能与外观**：P1-07（TXT）、P1-09（搜索）、P1-10（书签）、P1-11（字体）、P1-12（亮度/背景）、P1-13（全屏/进度）、P1-14（封面）、P1-08（固定版式识别）。

**交付判定**：一本标准公版中文书在 M2 后应「看不出与商业阅读器的排版差距」（首行缩进、居中标题、加粗、插图、脚注可用）。

### M3 — 打磨（P2，8 条）

**范围**：P2-01 ~ P2-08。其中 **P2-08（打开方式接入）** 若负责人在 Q1 中愿意扩大平台依赖范围，可提前到 M1 末期（它是「用起来顺手」的关键一环）。

**交付判定**：日常使用中不再需要「回到 App 里手动找书」。

### 跨里程碑的持续项

| 项 | 要求 |
|---|---|
| 回归测试 | 14 本 fixture + `baseline.json` 每一次提交都必须通过；新增能力（TOC、图片、TXT）应各自补充 fixture |
| 真机验证 | 每个里程碑至少在 **小米 HyperOS/Android 16 手机** + **Windows 桌面**各跑一次完整流程 |
| 文档同步 | README 的「已知限制」章节随每个里程碑更新，避免文档与产品状态脱节 |
